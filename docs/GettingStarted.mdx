# Getting started

## 1. Install

Install a released version straight from GitHub, pinned to its tag:

```sh
npm install github:diki-stwn/serupa-ds#v13.0.0
```

Pin a tag, never `#main`, so updates reach your project only when you choose. Each release tag is prebuilt, so nothing runs on install.

**Updating:** change the tag and read the [Changelog](?path=/docs/changelog--docs) entries in between. Minor and patch releases never remove anything; major releases list what changed and how to migrate.

## 2. Use it in a React app

Vite, Next.js, Remix or any bundler. React 19 is a peer dependency, so the components use your app's React. The package needs Node 22 or later (working on this repository needs Node 26).

```js
import 'serupa-ds/tokens.css';
import 'serupa-ds/base.css';     // page defaults; skip it when adding the system to an existing app
import 'serupa-ds/bundle.css';   // or components.css, plus utilities.css if you use the classes
import { Button, Field, Input } from 'serupa-ds';

export function SignUp() {
  return (
    <form>
      <Field label="Email" required><Input type="email" /></Field>
      <Button type="submit">Create account</Button>
    </form>
  );
}
```

A bundler hashes the file names and compresses them for you, so of the delivery notes under Before you ship only the CSS choice applies there. For router links, set the link component once at startup: `configure({ link: Link })`. For another language, wrap the app in `<SerupaProvider locale="id-ID" labels={idLabels}>` (see [Localization](?path=/docs/guides-localization--docs)). The components render on the server too, and types ship with the package.

## Or on a plain page

```html
<!doctype html>
<html lang="en" data-brand="blue" data-mode="auto">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Hello · Example</title>
  <script src="dist/theme.js"></script>
  <link rel="preload" href="fonts/InterVariable-latin.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="stylesheet" href="tokens.css">
  <link rel="stylesheet" href="dist/base.css">
  <link rel="stylesheet" href="dist/components.css">
</head>
<body>
  <main id="root"></main>
  <script src="dist/lib/react.production.min.js"></script>
  <script src="dist/lib/react-dom.production.min.js"></script>
  <script src="dist/serupa.iife.js"></script>
  <script>
    const { Button } = window.Serupa;
    ReactDOM.createRoot(document.getElementById('root')).render(React.createElement(Button, null, 'Hello'));
  </script>
</body>
</html>
```

The stylesheet is `components.css` (about 290 KB), not `bundle.css`, because a plain page links it as is and the browser waits for it before drawing anything: `bundle.css` adds every utility class, nearly 2 MB. If the page uses utility classes, link the output of `serupa-purge` instead (see Before you ship). `theme.js` stays in `<head>`, since it has to run before the first paint, and the other scripts go at the end of `<body>`. What else a page needs, its title, landmarks, skip link and focus after a route change, is in [Build a page](?path=/docs/guides-build-a-page--docs). Which component fits a job, among the ones that look alike, is in [Choose a component](?path=/docs/guides-choose-a-component--docs).

## 3. Pick a theme

`data-theme` on any element picks one of the six themes (`blue-light`, `blue-dark`, `violet-light`, `violet-dark`, `emerald-light`, `emerald-dark`). `theme.js` sets it on the page from `data-brand` and `data-mode`, follows the visitor's light or dark setting, and remembers a choice made with `Serupa.theme.set()`. Load it first in `<head>` so the page never flashes the wrong theme. A switch changes every color at once, with no control fading on its own, while motion such as a menu fading out runs on (to switch a section yourself, use `withoutTransitions`). It also keeps `<meta name="theme-color">` on the page's surface, so a phone's status bar and address bar change with the mode; a `theme-color` meta the page writes itself is left as it is. See [Themes](?path=/docs/foundations-themes--docs).

## 4. Before you ship

- **Trim the CSS.** `bundle.css` carries every utility class (nearly 2 MB). `npx serupa-purge src -o public/bundle.min.css`, which comes with the package, keeps the component styles (about 300 KB) and only the utility classes your code uses. Add `--components` to keep only the styles of the components your code names.
- **Compress and cache the files (plain page).** Serve them with Brotli or gzip: `bundle.css` goes from 2 MB to about 110 KB with Brotli, and `components.css` to about 30 KB. The file names in `dist/` and `fonts/` carry no hash, so serve them from a folder named for the version (`/serupa/<version>/`) and cache them for a year: an update is a new folder, never a changed file under an old name.
- **Fonts and icons are included.** `tokens.css` loads Inter from the package's `fonts/` folder, and icons are SVGs inside the components. Nothing loads from another server. Every Material Symbol works by name, such as `<Icon name="category" />`. On a plain page, an icon outside the everyday set loads `serupa-icons.iife.js` from beside `serupa.iife.js` the first time it's drawn, so copy the two together. The icons drawn by name load as separate files the first time a page uses them, so your bundler must split dynamic imports (Vite, Next.js, webpack and Rollup do by default). A single-file build without splitting takes in the whole icon set, about 510 KB gzipped: see Icon's Usage.
- **A strict Content Security Policy works.** The package never uses `eval` or an inline script, and everything loads from your own server, so `script-src 'self'; style-src 'self'; font-src 'self'` is enough for a React app. On a plain page, move the inline `<script>` above into a file of its own (or give it a nonce). One thing to know if you render on the server: a policy without `'unsafe-inline'` in `style-src` (or `style-src-attr`) makes the browser ignore `style` attributes in the server HTML, and hydrating keeps them as sent. Progress, Meter, Slider, Rating, TreeView, Splitter, ColorPicker, AvatarGroup, Icon, Carousel, Image and Textarea apply theirs again right after hydration, through the DOM, which the policy allows, so they work under it. Grid and Stack stay Server Components, which don't hydrate, so their columns and gaps need `style-src-attr 'unsafe-inline'` in server HTML. A `style` you pass to any other element in server HTML is still ignored until it next changes. If you rely on one, add `style-src-attr 'unsafe-inline'`, which allows style attributes and nothing else (no `<style>` elements, no stylesheets from elsewhere). A page rendered only in the browser needs none of this, because React sets styles through the DOM, which the policy allows. Trusted Types work too (`require-trusted-types-for 'script'`) with no policy, because nothing in the package writes HTML, your custom icons included.
- **Console warnings are for development.** A component warns once in the console about a mistake it can see, such as an icon-only button with no label or a Tabs value that matches no tab. Your bundler's production build (`NODE_ENV=production`, the default for `vite build` and `next build`) drops the warnings and their text. On a plain page, `serupa.iife.js` keeps them.
- **Accessibility comes with the components,** but labels are yours: give every field a `Field` label, every icon-only button an `aria-label`, and check each component's Accessibility notes.

## Lint your JSX for accessibility

eslint-plugin-jsx-a11y checks a plain `<img>` for its `alt`, but it skips a component it doesn't know, so `<Image src="team.png" />` with no `alt` passes. `serupa-ds/eslint` tells it what each Serupa component renders (Image is an `img`, Link an `a`, IconButton a `button`), so the same rules check them. Add it after the plugin's config in `eslint.config.js`:

```js
import jsxA11y from 'eslint-plugin-jsx-a11y';
import serupa, { labelAttributes } from 'serupa-ds/eslint';

export default [
  jsxA11y.flatConfigs.recommended,
  serupa,
  // Optional: IconButton and TableSelectCell take their name as label.
  { rules: { 'jsx-a11y/control-has-associated-label': ['error', { labelAttributes }] } },
];
```

It sets the settings for eslint-plugin-jsx-a11y and for its maintained fork, eslint-plugin-jsx-a11y-x, so it works with either. Oxlint reads the same `jsx-a11y` settings from `.oxlintrc.json`. Print them once with `node -e "import('serupa-ds/eslint').then((m) => console.log(JSON.stringify({ settings: m.default.settings }, null, 2)))"` and paste them in, then print them again after you update the package.

## Lint your CSS for raw values

A hex color in your own CSS doesn't change in dark mode, and a `13px` gap sits off the spacing scale. `serupa-ds/stylelint` is a Stylelint config with three rules that flag those values and name the token to use instead. Install `stylelint`, then extend the config in `stylelint.config.js`:

```js
export default {
  extends: ['serupa-ds/stylelint'],
};
```

- `serupa/no-raw-color` flags a color written out, such as `#333`, `rgb()`, `oklch()` or `black`. A color name only counts in a property that takes a color, so `grid-area: tan` passes. Use a color token, such as `var(--text)` or `var(--surface)`.
- `serupa/no-raw-spacing` flags a fixed length, such as `12px` or `1.5rem`, in `margin`, `padding`, `gap` or `inset`. A percentage or a viewport or container unit, such as `inset: 50%` or `1vw`, passes, because no token says that. Use a spacing token, such as `var(--spacing-4)`.
- `serupa/no-raw-radius` flags a length in `border-radius`. Use a rounded token, such as `var(--rounded-md)`.

These values always pass: anything inside `var()` (including its fallback), `calc()` over tokens, `0`, `transparent` and `currentcolor`, and the values of custom properties, since that is where your own tokens go. When a line needs a raw value, say why in a comment: `/* stylelint-disable-next-line serupa/no-raw-color -- the logo's exact ink */`.

## Working on the system

```sh
npm install
npm run storybook   # these pages, at http://localhost:6006, updating as you edit
npm test            # builds the package and runs every test, including axe in all six themes
npx changeset       # describe your change and pick patch, minor or major
```

Each component lives in `src/components/<Name>/`: the component (`<Name>.tsx`), its styles (`<Name>.css`), its component tokens (`<name>.tokens.json`), its usage guide (`README.md`, shown on its page here), its stories (`<Name>.stories.tsx`), its page (`<Name>.mdx`) and a `preview.html` for the visual tests. Its tests are in `tools/test/`. Write the usage guide from [the template](https://github.com/diki-stwn/serupa-ds/blob/main/docs/usage-guide-template.md) (`docs/usage-guide-template.md`): when to use it, when not to, usage, accessibility, props and component tokens.
