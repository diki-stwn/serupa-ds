# ADR-0002: Edit tokens in the repo and generate every output from them

**Status:** Accepted
**Status when written:** Proposed
**Checked against main (31 October 2026, 11.0.0):** Done: `tokens.json` is the source, and `npm run tokens` (tools/tokens/build.mjs) writes `tokens.css` and `design-tokens/` from it.
**Date:** 2026-10-17
**Deciders:** Diki

## Context

The token source is `tokens.json` at the repo root, in the **design system page's** format (the frozen artifact). From it:

| Output | Generated by | Committed? |
|---|---|---|
| `tokens.css` | **the design system artifact page** ("open the page and save once") | yes |
| `design-tokens/*.json` (DTCG) | `tools/tokens/export.py` (Python) | yes |
| `design-tokens/components/*.json` | copied from `src/components/<Name>/*.tokens.json` | yes |
| `src/styles/utilities.css` (1.8 MB, 25,561 classes) | nothing: hand-maintained, originally made by the page | yes |
| Style Dictionary build | `tools/tokens/style-dictionary.config.mjs`, used only as a test | no |

`tokens.css` hasn't changed since the import commit. **No tool in the repo can regenerate it**, and `foundation.py` fails with "save the design system page" when it falls behind `tokens.json`. The page is frozen at v4.7.0. So today, adding or changing any token blocks CI, and the only way through is editing a 73 KB generated file by hand. The format also carries the page's limits (12 extra groups, 60 tokens a group, `bundle.css` under 2 MB), which no longer apply.

The test helper `tools/test/lib.mjs` already contains a working `tokens.json → CSS` generator (`tokensCss()`), so most of the logic exists.

## Decision

Make the repo the only generator. One Node script (`npm run tokens`, run by `npm run build`) reads the token source and writes `tokens.css`, the DTCG export and the utility classes. Keep the current variable names and the current `tokens.css` output byte-for-byte equivalent, so it's a minor (or patch) release.

## Options considered

### A: Keep the artifact-era pipeline (current)
| Dimension | Assessment |
|---|---|
| Complexity | Low today, but it blocks every token change |
**Pros:** no work. **Cons:** token changes can't pass CI; two languages; outputs committed and drifting. Not viable.

### B: Promote `lib.mjs`'s generator into a Node build step (recommended)
| Dimension | Assessment |
|---|---|
| Complexity | Low: the generator exists; move it, add comments and `@font-face`, compare output |
| Risk | Low: diff the generated `tokens.css` against today's committed one; they must match |
| Languages | Node only for the build (Python can stay for audits until they're ported) |

**Pros:** unblocks token work this week; non-breaking; no new dependency.
**Cons:** keeps a homemade format and generator to maintain.

### C: Move to DTCG source files and let Style Dictionary 5 generate everything
| Dimension | Assessment |
|---|---|
| Complexity | Medium–high: new source layout, custom formats for the system's names, comments and per-theme blocks |
| Fit | Standard format Figma plugins (Tokens Studio) read and write directly |

**Pros:** industry standard; one format from Figma to CSS to iOS/Android later. **Cons:** bigger change; the source moves (needs Diki's OK under the "ask before renaming tokens" rule, even if CSS names don't change).

## Trade-off analysis

B fixes the blocker with the least risk and keeps the door open to C: once generation lives in the repo, swapping the source format to DTCG is a contained follow-up. C is the better end state but shouldn't hold up token changes. Generating `utilities.css` from tokens belongs in the same script, so a new spacing or color token gets its classes automatically instead of by hand.

## Consequences

- Easier: adding a token, a brand (ADR-0003) or a scale step becomes one source edit.
- `tokens.css` and `design-tokens/` can stop being committed and move to `dist/` at 5.0 (moving the export paths is breaking; until then the build writes them to their current paths).
- The 2 MB and "60 tokens a group" checks in `foundation.py` should be dropped; they were the artifact's limits.
- Revisit: whether to do C before or after 5.0.

## Action items

2. [ ] Replace the "save the design system page" check with "generated file is up to date".
3. [ ] Port `export.py` to the same script, so the build needs Node only.
4. [ ] Generate `utilities.css` from tokens; the existing 25,561-class baseline proves nothing changed.
5. [ ] Later, if wanted: DTCG source + Style Dictionary (option C).
